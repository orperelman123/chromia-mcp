# The goal

**This MCP must make it as easy as possible for an agent to build secure Chromia dapps and chains — and the dapps it produces must be ones an auditor cannot drain.**

Everything else in this repo serves that. When a change is worth making, it is because it moves this; when a claim is worth doubting, it is because it only appears to.

## The bar: zero exploits

**A dapp built from this MCP must contain no exploit an auditor can land. Zero — not "fewer than last round".**

That is a number a round can fail, and most rounds have. It is not "the gate returned `ok:true`" — that is a linter result, and on 2026-09-02 it certified four agent-built dapps of which two were trivially drainable. The test is always:

> An agent builds a dapp using **only** this server's guidance, templates and gates. An independent hostile auditor then attacks it. Whatever they can drain is our failure, not the agent's.

**A round passes only when the auditor reports that they could drain nothing.** Anything less is a red round, however much coverage moved. Two things follow from that, and both have already bitten:

- **A drain in a class we have no template for is our failure too.** Every un-templated class attacked so far has drained. "We never claimed to cover streaming" is not a defence — the agent asked this server how to build, and this server answered.
- **The prose is part of the attack surface.** Round 7 drained a build whose author followed the template header exactly: the header prescribed a holding period against a step in pool value, and the attack was exit-only, so the advice was the vulnerability. A header sentence that is wrong is a defect of the same kind as a missing guard, and the residual list — where an auditor places the most trust — is the worst place to be wrong.

Run it as a round: build, attack, pin what got through, fix, re-attack. `app/src/test/resources/exploit-corpus/` is the standing scoreboard — every exploit found becomes a sample with a pinned verdict, so coverage is measured on every build instead of claimed in a report.

## Four principles, in priority order

1. **Guidance must not manufacture bugs.** A template that teaches an insecure pattern outranks any missed detection: it *creates* the hole. Defaults are what agents copy, so the default must be the safe one. (The scaffold once shipped `add_auth_handler(flags = [])` as the golden pattern; FT4 resolves flags with `contains_all()`, and `contains_all([])` is always true, so every value-moving operation copied from it silently dropped the Transfer flag.)
2. **Detection must not be evadable.** A rule keyed on anything the attacker chooses is not a boundary — key on **type and use, never on names**, and attack your own rule before shipping it. (`authorization-not-bound-to-caller` once matched a parameter-name allowlist: HIGH as `from`, silent as `victim`, same drain. The same evasion class then appeared three more times, and was finally systemic in a shared helper.)
3. **The gate must not cry wolf.** A gate agents route around is worse than no gate. A rule that cannot be made precise is **dropped, with the reasoning stated** — not shipped noisy. Undecidable properties (conservation, quorum) stay MEDIUM advisories and never make `ok:false`.
4. **What cannot be caught statically needs a different answer** — a template that makes the bug unwritable, a test the scaffold ships, or a runtime check. Never a regex pretending. The `governance`, `vault` and `staking` templates exist because their exploits are undecidable from syntax; each ships the original drain as a must-fail test.

## Never claim more than is true

`ok:true` reads to an agent as an audit pass. The notes must state the boundary, gaps must be named rather than rounded up, and a lane stays red rather than being closed by softening its assertion. **A fake green is worse than a red** — every one this project shipped came from evidence that looked like proof: a cached build that ran nothing, an empty results directory read as zero failures, a mutant that "went red" because the chain failed to start, a rule that passed every test its author wrote.

`scripts/loop-gate.mjs` is that discipline as a command. Use it instead of reading a build log.

## Where things stand

**Not met.** Twelve templates ship, and the record is still the same shape it has been since round 1: **every un-templated class attacked has drained** — nine rounds, nine classes — and four *shipped* templates now carry recorded drains (lending twice, staking, governance). Every one of those was certified `ok:true` with zero findings and every conservation invariant exact. The scoreboard is `app/src/test/resources/exploit-corpus/CORPUS.md`; read it rather than this paragraph.

Two findings outrank any single drain, and both were in the gate itself:

- **The gate disarmed on every real project.** Adding the `@test` module the scaffold ships - and `run_rell_tests` requires - reclassified `main` as test surface, downgraded every production HIGH to advisory and flipped `ok` to true. It was armed only for a `main.rell` submitted with no tests, the one shape a real project never has. Fixed, pinned in three shapes including the rename evasion.
- **An object field write was not a mutation.** `config.fee = f` matches none of `create|update|delete`, so an unauthenticated operation whose only write was an object assignment drew no finding - and the default template taught exactly that spelling. The corpus row for the class was `CAUGHT` the whole time, on the *other* spelling. **A corpus row proves the sample is caught, not the class.**

The drains that were not missing guards were wrong sentences. Rounds 7, 8 and 9 were each topped by a defect in our own prose - a prescribed holding period that *was* the vulnerability; a claim that a monotone counter "can never rewrite the past"; a seam citing a victim's 144 bps execution loss as the pool's 79 bps reserve movement. Three of the defects found on 2026-09-03 were introduced that same day while fixing others. A green suite cannot tell whether a sentence is true, so the arithmetic a header cites is now recomputed *in a test* from the template's own constants, and the honest rule is: **every claim in the guidance is either testable or deleted.**

Closed on 2026-09-05, each with a replay and a mutant where a guard changed: round 9's three prose drains - the AMM's "more than 1500" is stated as a floor with no ceiling and the seam no longer tells authors to re-quote into a moved pool; the lending residual's "only against an already-insolvent position" was false because a liquidation *created* insolvency below 110% backing, so `liquidate()` now refuses to leave a solvent position insolvent and pays an under-water one value for value with no bonus; seam 2 now says a position is not transferable before it matures, since the confederate only ever had to pay. Also closed: the AMM's first-depositor "never a silent haircut" claim (a deposit must be redeemable for what it deposited, to a unit of rounding) and the marketplace's miscounted guards. Round 10, found by reading the governance header, is closed in the template with replay and mutant.

**The discipline is now a tool.** `verify_guards` runs the mutant check on an agent's own dapp: a guard is reported `load_bearing` only if its must-fail test passes with the guard and fails without it *because the attack landed*; a test that stays green without its guard is reported `vacuous`, and every environmental or wrong-reason failure is named rather than counted. It is step 4 of the agent loop, and it is attacked the round it ships, because a false verdict from a verification tool is a finding of the same rank as a drain.

**Round 11 (2026-09-06) failed twice over, and the second failure was the tool.** `verify_guards` gave six wrong verdicts in its first round, four of them `ok:true` - it searched raw text where comments live, replaced every copy in a file, classed a header-less test sibling as production, let `alsoRemove` carry a vacuous guard on a real one's back, and let a caller's fragment outrank the guard's own refusal. Each is closed and each probe is now a test (`VerifyGuardsProbeTest`) pinned to the true verdict: a tool-verdict finding is pinned as a test, and every verification tool ships with its own `*ProbeTest`. The round's two template drains are closed the same way, each with a replay and a mutant that reddens it because the attack lands: governance registration now mints NO voting weight (weight is a one-time founder-countersigned genesis allocation, capped, and the window closes once the DAO has stake), a proposal's quorum is fixed from the stake that existed when it was created and each voter's weight is a snapshot taken then - so neither a free grant nor a two-point stake after voting closes can move the bar; and the stablecoin's `liquidate()` refuses while the system is under-backed at the fresh price, before or after the seizure, so settlement is the only exit and the shortfall is shared in any order. The lane that wrote those fixes stalled on its own gate; the orchestrator committed the work, found its "verification run" was a targeted build rather than the gate, and gated the merged tree on main before pushing. **The lesson of round 11 is that verification tools are attack surface**: `verify_guards` lied six times in its first round, and an agent would have trusted every one.

**Round 12 (2026-09-06) attacked the tool the round after its fix, and got three more false verdicts out of the one input round 11 left alone.** Round 11 guarded the SEARCH and the ERROR; nothing guarded the SUBSTITUTION. A replacement that refuses in its own words was read as the attack landing (`ok:true`); a replacement of `/*` commented the real guard out and credited a vacuous one with the drain (`ok:true`); an `alsoRemove` entry that contained the guard stripped it in the control run and called a load-bearing guard vacuous. All three are pinned as probes (`p7*`-`p9*`) and closed by refusing the input instead of guessing: the replacement's literals count as refusals, the masked file must be identical outside the replaced span (`replacement_rejected`), and `alsoRemove` must be disjoint from the guard (`also_remove_overlaps_guard`). The general lesson is sharper than round 11's: **every input of a verification tool is attack surface, not only its outputs** - a fix that hardens two of three inputs has told the next round exactly where to look. The round's template drains are closed the same way, each with the drain as a must-fail test and a mutant that reddens it because the attack lands. Governance: `committed_treasury()` had reserved the treasury for a REJECTED proposal, so one point of stake out of 2001 froze it through a 2000-to-1 vote; now only APPROVED proposals inside their window reserve against everyone, a proposer's own undecided proposals reserve against that proposer alone, an identical re-proposal is refused while the original is live, and the guarantee round 10 rested on is arithmetic - a proposal records `funded_at_creation` and executes only if `paid_total + amount` fits inside it. Its genesis window had closed on the first member's stake, so one hand held 100% of the weight; now only the founder's signed `close_genesis()` shuts it, the DAO is either in GENESIS (claims, no stake) or LIVE (stake, no mint), and the header says the cost out loud: a founder who never closes it leaves a DAO that can never stake. Stablecoin: the round-11 refusal was a floor at 100% while the bonus is 105%, so the `[100%, 105%)` band still moved 12 tokens on transaction order (101/117/81 against 89/124/86); the floor is now the BONUS - backing must clear 105% before and after a seizure - and the 47.00 fixture settles 89/124/86 in either order; capping the payout at par instead was measured and rejected (97/117/85). And the un-templated order book, built from this server's own two sentences and drained because a partial fill's delete-and-recreate reset the maker's cancel clock (1000 kept where an uninterrupted maker keeps 2000), is the ELEVENTH template, `exchange`: terms immutable, one monotone `filled` counter so a row is never recreated and `created_at` is written once by the maker, the book matches (there is no `fill_order(id)`), and a crossing order fills at the resting price. Guard counts in headers are now measured by a test, because the stablecoin header said "Six" above seven guards. **Still open from round 12:** the stablecoin's `settle()` is permissionless and takes a HEALTHY position's collateral into a pool paying under par while that debtor could have burned at par and withdrawn in full - measured at 48.00 as 111/88 settle-first against 100/100 burn-first (`adversary-round12/attacks/stable_r12b.rell`); it is not yet a corpus row and not yet fixed.

**Round 13 (2026-09-06) failed twice over again, the round after the exchange shipped and the round after the tool's second fix.** `verify_guards` gave two more false `ok:true` verdicts, and the shape is the one rounds 11 and 12 should have predicted: each of those fixes read ONE MORE source of refusal messages (the guard's literals, then the replacement's) and left the caller's `attackLanded` fragment free to match any refusal from anywhere else - a second `require()` on the next line (defence in depth, which is exactly what a careful author writes), or a bound that lives in `module_args` and appears in no file at all. The fix is finally structural rather than an ever-longer list: **a refused transaction is never the attack landing.** The runner's own `Operation '...' failed` shape and every production file's string literals are refusals, read from the chain's half of a `run_must_fail` mismatch only, and the caller's fragment is consulted for what remains - a test-side assertion. `p11`/`p12` are pinned green; five other inputs (case-colliding paths, `..`, duplicate test names, a `module.rell` retyping the guard's module, BOM + non-ASCII) were attacked and held (`p13*`). The template drains are closed the same day, each with the drain as a must-fail test and a mutant that reddens it because the attack lands (the fixes follow the lesson): governance, where paying a member by proposal mints voting weight out of the treasury - `execute_proposal` retires no stake and there is no unstake - so 1000 allocated points became 4000 of weight and took 2000 of honest stake against a unanimous NO (bar 3500 from 7000), invited by the header's own "to give somebody weight after genesis, pay them by proposal"; the stablecoin's `settle()` taking a healthy debtor's par exit (111/88 against 100/100 at 48.00, the round-12 open item, now a row) and `withdraw_collateral` reading only the position while every other value-moving operation reads the system, so a whale withdraws 99 of 100 tokens and settles in the same block from 149% backed; the new exchange's `best_resting()` being an unfiltered `order @* {}` - the header's "index price and side" cannot be followed and the same ten trades took 1.8s / 7.4s / 26.3s behind 0 / 50 / 150 dust rows and were abandoned behind 300, one free registration paying for 10,000 rows; and recurring pull billing, built from the `streaming` redirect with every carryable guard carried, drained because the one guard that template rests on - PREPAID - has no analogue in a pull model, so `cancellable = false` became an irrevocable uncapped claim that took all 9,990 points the payer held, and the period boundary is a whole-fee step where the streaming header promises "one unit". The twelfth template, `subscription`, is the answer to the last two. Three prose defects were measured too - the governance claim that "two approvals are never sold the same money" (both are; the second is refused only at execution), a `GENESIS_POINTS` comment still describing round 12's drain as current behaviour, and the exchange's un-followable index advice. **The lesson of round 13**: a verification tool's verdict must come from the STRUCTURE of the evidence, not from a growing list of exceptions - every list has a next item, and the adversary finds it the round after it is written.

The round-13 fixes: governance treats the treasury and the voting weight as ONE pocket - a payout retires the stake that backed it, pro rata across stakers in a canonical order, so `dao.total_stake == dao.treasury_balance` at every block and total weight can never pass what genesis allocated (the four-turn ratchet leaves 1000 of weight, and the 2000-point vote loses 1000 to 2000 against a bar of 1500); the stablecoin's `withdraw_collateral` clears the same bonus floor `liquidate()` does, at a fresh price, with no exception for a debt-free position, and settlement is two calls a `SETTLEMENT_WINDOW_MS` apart during which only the two backing-RAISING operations run, so a debtor's par exit is available in either order (54 out / 46 kept both ways, where round 13 measured 111/88 against 100/100) and a whale's 99-token withdrawal is refused; the exchange's matcher selects with a where-clause on side, price and the taker's own id served by `index is_buy, price`, and `MAX_RESTING_ORDERS = 20` bounds the book per trader, pinned by a shape test rather than a stopwatch; and the twelfth template, `subscription`, makes the merchant's whole claim the escrow the payer funded, accrues the fee pro rata so no boundary is worth straddling, and lets either party cancel at any time - there is no `cancellable` term, and the header says why one cannot exist in a pull model. **Open from round 13:** the static rule `unbounded-voting-period` is keyed on a parameter NAME (`period|window|duration`) and fired MEDIUM on the subscription template's `amount_per_period`, a money parameter - principle 2 in reverse, an advisory on correct code; it is not yet a corpus row and not yet fixed. And round 13's own evidence carries arithmetic slips the fix lane caught (a 98-token probe described but not coded in `stable_r13.rell`, `203 * 48` where the code withdraws 99 of 300, and a "400-row" tier that the shipped fixture tops out at 300) - the corpus citations now say 300, the attack-file comments are left as the round wrote them.

**Round 14 (2026-09-06) failed on all three counts - five template drains, a DoS, a drained bridge, four static rules firing on correct code, and three more false `verify_guards` verdicts, this time in the conservative direction.** Round 13's structural rule read ANY refusal as "the attack did not land"; round 14 showed a refusal from a LATER operation after the attack landed, a test-side `require()` in production words, and a diagnostic string carrying its own `but was <...>` - each turned a genuinely load-bearing guard into `still_refused`, and an author's fix for that is to weaken the test until the tool likes it. The rule now compares the runner's failing frame with the declaration the guard lives in: a refusal from the guard's own operation is `still_refused`; anything else red on a test that was green with the guard is the damage being noticed, and no string literal is consulted at all. `p14a`-`p14c` pinned green; `p14d`/`p14e` held. The template drains are closed, each with the drain as a must-fail test and a mutant that reddens it because the attack lands (the fixes follow this paragraph): the subscription's time ceiling derived from CURRENT funding (a top-up pays for eleven unfunded months in one block, 10000 taken) and its "one unit" staircase that is a block's worth of fee (2778 units on the largest fee and shortest period); the exchange's per-ACCOUNT self-dealing rule while registration is free (a second key cancels inside `MIN_RESTING_MS`, 500 points off an honest maker) and market-priced dust on free registrations (2.8s -> 16.6s behind 100 rows); governance retirement rounding UP in sort order so the first owner pays every rounding point (a two-point payout takes 100% of a one-point staker); the stablecoin's debt-free depositor frozen in the bonus band, the failing position voiding the settlement opening in the block it acts, and one honest post inside the window moving 7 of 71 surplus tokens; and a bridge receiver built from the `ft4` redirect - "copy the transfer-conservation test", which is structurally blind to a mint - paying one burn ten times (10000 from 1000) and three accounts 256000 against one burn: the thirteenth template, `bridge`, is the answer. **Four static rules key on identifier NAMES** (`unbounded-voting-period`, `majority-without-quorum`, `query-returns-secret-data`, `value-sink-without-withdrawal`): renaming one identifier silences each, and the first had already written `MIN_FEE = 1` into the shipped subscription template to keep the gate quiet - principle 2 in reverse, pinned as four `FALSE_POSITIVE` rows and in a lane to be rebuilt on structure.

The round-14 fixes: the subscription's funding buys time FORWARD from the moment it arrives (never time already passed), and the boundary step is bounded at one unit per second of the period (the runner's ten-second block is a ten-unit step, where round 14 measured 2778); the exchange's resting order is a commitment whoever fills it (a maker's proceeds inside `MIN_RESTING_MS` stay locked, so a second key buys nothing) and the book is bounded by `MIN_NOTIONAL` - something an attacker pays for - rather than by free registrations; governance retirement is pro rata by largest remainder, so the odd point moves and no staker is emptied by a payout smaller than their stake; the stablecoin's backing is the DEBTORS' collateral, so a debt-free depositor withdraws regardless of others' debt, and a settlement opening is resolved once, at its window, never voided in the block the failing position acts; the thirteenth template, `bridge`, keeps a processed-burns registry that is a database key, holds every attestation to the burn it opened by a `require` pair, mints only at the relayer threshold, and counts minted units against attested burns; and the four name-keyed rules are rebuilt on structure with a rename-invariance test - the four `FALSE_POSITIVE` rows are `CLEAN`. **What this round taught about the loop itself:** neither fix lane ever got a build slot, and the gate on the merged tree found five defects they shipped blind (a compile error, a wrong mutant, a query-clock pin, a redirect pin for a name that had become a template, a flag regex) plus one of the orchestrator's own - the first version of the timestamp exclusion used the clock-fed DATA-FLOW set and hid the round-4 mint behind ten reds; the exclusion is the DECLARED type only. Two gates were killed at the 45-minute cap by memory contention with 3.6 GB free on a 32 GB box, with their results deleted; the cap is 60 minutes and the build slot is written down as a memory rule. Also shipped: the MCP Kotlin SDK 0.7.7 -> 0.15.0 with Streamable HTTP at `/mcp` beside SSE, a `public` tool profile pinned by a compile-time marker (a strategy that does not say whether it touches the machine does not compile), and a Host allow-list on both endpoints; and the first **agent-experience audit** - a read-only lane driving the jar exactly as a fresh agent would - measured ten defects that no adversary round had seen: the docs index depended on the process's working directory (a registered install silently served a 320-day-old index), `search`/`fetch` never said so, the onboarding text claimed human blockers for steps this server automates, the flagship `ft4` template's own tests went red on the honest first run, `write_deployment_config` regenerated a gutted `chromia.yml` that `validate_chromia_yml` blessed, eighteen plausible aliases scaffolded `hello` with `isError:false`, every scaffold carried the same 22 KB of notes, and three names for the Rell sources. Those fixes are on a branch with a test built from each audit call, gated next. The QA loop is now the third loop this repository runs, and its bar is the same: a measurement, pinned as a test, or nothing.

What holds: each template makes its own exploit class unwritable rather than detected, and every guard has a mutant that reddens a shipped must-fail test *because the attack lands* - a mutant that goes red for any other reason proves nothing, and one was caught doing exactly that. `scripts/loop-gate.mjs` is the merge discipline as a command; `docs/ADVERSARY-ROUND-BRIEF.md`, `docs/TEMPLATE-GAPS.md` and `docs/AGENT-LANE-BRIEF.md` are the method, so a session can be picked up cold.
